# AGENTS.md — Samho TPM (Maintenance Management)

## Stack

- **Frontend:** Vanilla HTML5 + CSS3 + ES6 — no frameworks, no bundler, no build step.
- **Backend:** Supabase (PostgreSQL + Auth + Storage), accessed directly from the browser via REST.
- **Dependencies (all CDN):** Lucide icons, SheetJS/xlsx, ZXing barcode, Google Fonts (**Be Vietnam Pro** — the only font loaded on every page; Vietnamese-correct, replaces Inter).
- **Config:** All Supabase URL/keys, table/column mappings, and Power BI embed URL live in `supabase/config.js`.
- **Auth:** Supabase email/password; session persisted in `localStorage` under key `samho.auth.session`. Users log in with a short ID — it gets `@email.com` appended automatically (`auth.js:toAuthEmail`).

## Commands

No package manager, no build, no test, no lint, no typecheck, no CI. Open any `.html` in a browser or serve with any static server:

```sh
python -m http.server 8080
npx serve .
```

Admin scripts live in `supabase/`: `update-display-name.js`, `sync-users.mjs`, `prune-users.mjs` (all ESM). They require the Supabase service_role key and are all `.gitignore`-d — never commit them. The two `.mjs` scripts read the key from the `SUPABASE_SERVICE_ROLE_KEY` env var (set it inline, e.g. `$env:SUPABASE_SERVICE_ROLE_KEY="..."`), not from the file itself.

Build script: `scripts/convert-pm-excel.js` regenerates `data/pm_master_data.js` from `Master Data - PM - TECH.xlsx`. It needs the `xlsx` npm package (`npm i xlsx`) and reads from `data/`.

## Key Conventions & Gotchas

- **Backup once only** — before the *first* edit of a file, create a single backup (`file_backup.ext` or `file_backup_YYYYMMDD.ext`) **only if one does not already exist**. Do **not** create a new backup on every later edit; continue on the working copy (`_edited` / `_v2` / `_v3`…). Git is the safety net for subsequent changes. Per-edit HTML/JS/CSS backups were deleted (2026-09-23); do not reintroduce them.
- **Script loading order (all pages use `defer`):** `config.js` → `auth.js` → `errors_edited.js` → `i18n.js` → `datetime.js` → `db_client.js` → `sidebar.js` → (CDN deps if needed: `@zxing/browser` on `repair_submit` & `red_tag`; `xlsx` on `repair_info` & `incoming_stock`) → page-specific JS. `repair_submit` uses `app_edited.js`; `repair_info` uses `app_edited.js` + `repair_info_edited.js`. The `_edited` suffix indicates the file has been modified from the original. The original un-edited forks (`app.js`, `repair_info.js`, `red_tag.js`, `kpi_dashboard.js`, `pm.js`, `errors.js`) were deleted — only `_edited`/module files exist now.
- **No cache-busting standard** — some pages use `?v=YYYYMMDD-N`, most do not.
- **Bilingual UI** — full VI/EN toggle across all pages via `window.SAMHO_LANG` (`assets/js/i18n.js`), loaded after `errors_edited.js`. Static text uses `data-i18n`/`data-i18n-ph`/`data-i18n-title` attributes; JS-generated strings use `SAMHO_LANG.t(id, {vars})`. Dictionary: shared base keys (nav.*, login.*, common.*, error.*, bm.*, repairInfo.*, greeting.*, app.*, loading.*) live in `i18n.js` via `SAMHO_LANG.register`; page-specific keys (kpi.*, redtag.*, spare.*, incoming.*, pm.*) are registered at the top of each page JS. Default `vi`; choice persisted in `localStorage` under `samho.lang`; a change dispatches a `samho:langchange` event (`detail: {lang}`) — every page JS adds a listener to re-render its data. `repair_submit` issue/solve `<select>` options keep Vietnamese `value` attributes so DB values + `syncOtherInputState`'s `"khac"` check still work; only the visible text is translated. The VI|EN toggle is anchored **in the page** (absolute top-right; scrolls away with the content, not pinned to the viewport), **bigger, non-draggable** (no pointer-move handlers).
- **Font** — every page loads only `Be Vietnam Pro` (Google Fonts `family=Be+Vietnam+Pro:wght@400;500;600;700;800`). The `--rs-mono` token in `styles_edited.css` also resolves to Be Vietnam Pro (Vietnamese-correct for machine-plate inputs). Do NOT add JetBrains Mono or Inter back.
- **Sidebar** — identical structure on all 7 dashboard pages: Maintenance group = BM → Repair Info → KPI Dashboard; TPM group = PM; Spare part group = Red Tag → Spare part → Incoming stock. The active page's link carries `class="current"`.
- **Modal-based CRUD** — all create/edit/delete uses dynamically generated modal dialogs, not separate pages.
- **Pagination** — handled by `db.select` (`db_client.js`): auto-paginates to completion at 1000 rows per page unless a `limit` cap is passed (which becomes a hard row cap).
- **Excel export** — uses SheetJS (`XLSX`) from CDN; available on `repair_info` and `incoming_stock`.
- **Barcode scanning** — prefers native `BarcodeDetector` API, falls back to `@zxing/browser` CDN.
- **Spare parts table discovery** — spare parts module tries multiple table names (`spare_parts`, `sparepart`, etc.) via `tableCandidates` in config.
- **Repair record `id` is UUID** — auto-generated by Supabase via `gen_random_uuid()` default on the `id` column. No manual ID generation.
- **Datetime format in DB** — `start_datetime`, `fix_datetime`, `end_datetime` stored as `dd-mm-yy hh:mm` (day-first, e.g. `13-07-26 02:53`). The `month` column stored as `mmm-yy` (e.g. `Jan-26`). All parsing/writing/display goes through the shared `window.SAMHO_DATETIME` module (`assets/js/datetime.js`): `fromInput`/`readInput` write the DB dialect from `<input type="date">`/`<input type="time">` values, `parse` reads it back (2/4-digit years, ISO `yyyy-mm-dd hh:mm`, compact `yyyymmdd`, or native Date strings), `toDisplay` renders `dd/mm/yyyy hh:mm`, `formatDate` renders date-only `mm/dd/yyyy` (PM due dates, red-tag dates), `downtimeMinutes` computes downtime, `monthKey` produces `yyyy-mm` KPI keys, `now()` returns local-time `{date, time}`, `addDays` shifts dates. **Local-time only** — `toISOString()`/`Date.UTC` are never used in the output path (avoids the DST/midnight day-shift bug).
- **Machine search** — `fetchMachineByCode()` queries `repair_records` then `machine_info` and merges results. BM form requires the code to be searched and loaded before submission.
- **Mechanic autocomplete** — calls Supabase RPC `list_user_display_names` (a `security definer` function exposing Auth user display names; SQL in `supabase/policies/`).
- **RLS** — Row Level Security is enforced via Supabase policies in `supabase/policies/`; the anon key is publicly visible by design.
- **RLS UPDATE silent no-op gotcha** — if a table's UPDATE policy has a `using`/`with check` expression that evaluates false, PostgREST applies the update to **0 rows** and returns success (`204`, or `200` with an empty `[[]]` body). The UI reports "Changes saved." but nothing persists. Symptom: edit button "works" but data never changes; delete still works (its policy is separate). This hit `repair_records` — the fix was SQL (run in the Supabase SQL Editor, not via REST): `drop policy ... for update ...; create policy ... for update to authenticated using (true) with check (true);`. Always verify a write by reading the row back (e.g. via service_role), since a 2xx does not guarantee the row changed.
- **No `.env`** — all config values are hardcoded in `supabase/config.js`.
- **Images** — spare part images stored in Supabase Storage bucket `spare_parts_img`.
- **Power BI** — embedded report URL configured in `supabase/config.js`.
- **Service role key** — `supabase/update-display-name.js`, `sync-users.mjs`, and `prune-users.mjs` are all gitignored admin scripts. The key is hardcoded only in `update-display-name.js`; the two `.mjs` scripts read it from the `SUPABASE_SERVICE_ROLE_KEY` env var. Never commit the key — a leaked key was rotated/removed from tracking (commit `61c8326`); rotate the Supabase secret if it was ever pushed.
- **Loading overlay** — global CSS spinner + JS utility (`SAMHO_LOADING.show()`/`hide()`) in `errors_edited.js`. Used across all pages during data fetches. Overlay is a fixed full-viewport element with opacity transition; spinner is a CSS border-animated circle.
- **`errors_edited.js`** — extends the original `errors.js` with the `window.SAMHO_LOADING` utility. All HTML files reference `errors_edited.js`; the original `errors.js` was deleted (no longer referenced).
- **Shared data layer (`db_client.js`)** — all Supabase REST traffic goes through `window.SAMHO_DB`, built by `window.createDbClient({ transport, anonKey, authHeaders })` (production instance: `config.url`/`config.anonKey` + `SAMHO_AUTH.authHeaders`, resolved lazily per request). API: `select`/`get` (auto-paginates when `limit` omitted), `getOne`, `insert`, `update`/`remove` (both refuse a filterless where — protects against mass PATCH/DELETE), `rpc`, `count` (exact via `Prefer: count=exact` + content-range), `discover` (probes `tableCandidates`, returns `{table, rows}`, NEVER mutates shared config — callers keep the resolved name locally, e.g. `activeSpareTable` in `spare_parts.js`), `friendly` (delegates to `SAMHO_ERRORS.message`), and low-level `request`. Filter grammar: primitive → `eq.<v>`; array → `in.(...)` (strings double-quoted); `{op, value}` → `<op>.<v>`; op-prefixed strings like `"not.is.null"` pass through verbatim; `[col, op, value]` triples allow duplicate columns (e.g. `gte`+`lte` on `due_date` in PM). **New code must go through `db.*` — never raw `fetch` + header triples.** The only exceptions: Storage endpoints in `spare_parts.js` (`/storage/v1/object`) and the login token exchange in `auth.js`.
- **PM module (`pm_edited_v3.js` active; `pm_edited.js`/`pm_edited_v2.js` historical)** — data-driven from `data/pm_master_data_edited.js` (pre-converted to `window.PM_MASTER_DATA`, no runtime XLSX). **Persistence is the Supabase `pm_records` table** (`config.pm.recordsTable`) — no localStorage. **Auto-insert of generated month rows was removed in v3** — `loadMonthRecords` only SELECTs the month range, filters `deleted=true`, and may backfill empty `name_en`; the only INSERT is manual `createPM`. **Plant filter is active on the PM page** — dropdown `#pmPlantFilter` + legend `#pmPlantLegend` in `pm.html`, driven by `scheduleFilter.plant` / `setPlantFilter` / `renderPlantLegend` in `pm_edited_v3.js`; filter applies to calendar, day modal, and schedule list (`getVisibleRecords`), with `#pmHiddenNotice` / `#pmDayHiddenNotice` when rows are hidden by the plant selection. **3-status flow:** ĐANG CHỜ → HOÀN THÀNH → ĐÃ XÁC NHẬN (`status` check: `pending|completed|validated`). Task checklist state lives in `task_progress` / `task_validation` (JSON arrays of task numbers) on the same row. Records carry `name_en`; written on manual create/edit. Delete is a soft-delete (`deleted=true`); display filters those out; manual create of the same `(item_code, due_date)` restores a soft-deleted row. Edit restricted to PID role on `record_type='manual'` rows. Schema: `pm_records_deleted_flag.sql`; also folded into `pm_rls.sql`/`pm_records_setup.sql`/`pm_records_live_schema_fix.sql`. Other pages (KPI, Repair Info, Red Tag, Spare Parts, Incoming Stock) still have their own plant filters.
- **Unified Button System** — appended to `styles_edited.css` (the active stylesheet; all HTML pages load it). One design language for every button: shared tokens (`--btn-*`) in `:root`, base geometry (text buttons 38px / 10px radius / 12px 800; icon buttons 36px square), consistent focus/press/disabled states, and semantic variants — primary/fill (`.btn`, `.save`, `.info-search`, `.login-form button`), success (`.btn.success`), muted (`.btn.muted`), danger (`.logout`), outline (`.repair-page-btn`, `.cal-nav`, `.quarter-pill`, `.repair-info-export`), ghost icon (`.icon-button`), close (`.repair-modal-close`, `.scan-close`). Mode/sub-mode tabs keep their color-coding. JS hooks (`.mode`, `.logout`, `.repair-page-btn`, `.pm-*`) unchanged. Per edit preference, the original `styles.css` is never edited — copy it to `styles_edited.css` first if further CSS work is needed.
- **PM task checklist source (`pm_tasks` table)** — the task checklist is fetched from the Supabase `pm_tasks` table (columns: `equipment`, `name_en`, `task_no`, `task_name`, `item_group`, `item_task`, `frequency`, `task_detail` — `machine_name` was renamed to `name_en`) filtered by `name_en = eq.<pm_records.name_en>` and ordered by `task_no`. Mappings live in `config.pm.tasksTable` and `config.pm.taskFields` (use `filterColumn` for the filter column) in `supabase/config.js`. If the record has no `name_en` or the table returns no rows, `openTaskModal` shows a warning — **no** local `taskCatalog` fallback. The table has no `est_hours`/`safety_note` columns, so the estimated-time badge renders empty. `task_detail` step strings already contain `1.`/`2.`/… prefixes; `openTaskModal` strips each line's leading number (`replace(/^\s*\d+[)\.、]\s*/, "")`) since the checklist renders in an `<ol>` — avoid double numbering. **`openTaskModal` map param must not shadow i18n `t`** — the checklist builder uses `tasks.map((task) => …)`; a `(t)` param collides with `t("pm.task.confirm")` for validators (`config.pm.validatorTeam`, e.g. `25102801`) and throws, so the modal never opens. **`openTaskModal` map param must not shadow i18n `t`** — use `tasks.map((task) => …)`, not `(t)`: validators (`config.pm.validatorTeam`, e.g. `25102801`) hit `t("pm.task.confirm")` inside the map and a shadowed `t` throws `TypeError` so `#pmTaskModal` never gets `.active` (fixed 2026-09-23 in `pm_edited_v3.js`; historical `pm_edited.js`/`pm_edited_v2.js` still have the bug but are not loaded). **`openTaskModal` checklist builder must not shadow the i18n `t` function** — `tasks.map((task) => …)` (not `(t)`); validators (`config.pm.validatorTeam`, e.g. `25102801`) get an extra Confirm checkbox that calls `t("pm.task.confirm")` inside the map, and a shadowed `t` throws `TypeError` so the modal never opens. Historical `pm_edited.js`/`pm_edited_v2.js` still have the bug (not loaded).
- **PM `pm_records` live schema gotcha** — the live Supabase `pm_records` table once lacked `record_type`/`technician`/`section` (and `created_at`/`updated_at`), so inserts (month-open generated rows, which always send `record_type`) returned `HTTP 400 {"code":"PGRST204","message":"Could not find the 'record_type' column ..."}`. Fix: run `supabase/policies/pm_records_live_schema_fix.sql` (ADDs the missing columns idempotently; unlike `pm_records_migration.sql` it does **not** drop `equipment`/`section`, which `createPM`/`editPM` still write). If you ever see PM page "Unable to load PM records" + a 400 in the console, re-verify schema drift before touching code.
- **PM machine config** — `supabase/config.js` has `config.pm.equipmentMap` mapping Excel equipment type names (e.g. `"ATOM FLASHCUT"`) to arrays of machine item codes. New equipment types added: EM CUTTING MACHINE, AUTO MARKING LINER, SEMI CUTTING, AUTO LASER HOLE PUNCHING MC, SOCKLINER (with plausible placeholder item codes — review before production use).
- **KPI Pareto drill-down** — the "Top 3 Areas by Downtime" rows on `kpi_dashboard.html` are clickable (`kpi_dashboard_edited.js::renderRankList`), opening a `repair-modal` Pareto chart of downtime grouped by `reason`. Buckets use normalized matching (trim + lowercase + collapse whitespace); empty `reason` rows are dropped; bars = top 8 reasons + a gray "Khác / Others" tail, with an SVG cumulative-% polyline + dashed 80% reference line. Data comes from the in-memory filter-respecting `lastRows` (stored in `renderDashboard`), not a re-query; the modal auto-closes on any filter change (month/plant/date). `reason` was added to `config.downtime.fieldMap` so the column is selected. Chart CSS (`.pareto-*`) appended to `styles_edited.css`. Bar heights rely on `.pareto-bar` being a flex column with **definite** height — a CSS-grid `align-content:end` track would collapse percentage bar heights.
